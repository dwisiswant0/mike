# Contributing

## Edit the canonical package

Only `internal/p308`, `internal/gen`, and `internal/asmgen` are written by
hand. The other per-prime packages, such as `internal/p374`, are generated:
each of their files starts with `Code generated by internal/gen`, and changes
to them are overwritten. In every per-prime package, including
`internal/p308`, `fp_amd64.s` is generated by `internal/asmgen`.

The files of `internal/p308` are copied to the other packages, so they must not
depend on the prime. Put prime-specific values in `internal/gen/params.txt` or
in the templates of `internal/gen`. The generator refuses to copy a file that
mentions `p308` or `633`, outside its package clause and package comment.

## Regenerate the packages

After changing `internal/p308`, `internal/gen`, or `internal/asmgen`,
regenerate the other packages and the `fp_amd64.s` files:

```sh
go generate
```

`internal/asmgen` uses [avo](https://github.com/mmcloughlin/avo) to generate
`fp_amd64.s`, the field multiplication with the BMI2 and ADX instructions.
It's a module of its own, so that the `mike` module doesn't depend on avo. Its
`go.mod` pins the avo release, which the first run downloads.

Tests in `internal/gen` and `internal/asmgen` fail when a generated file is
out of date.

## Run the tests

Run the tests, including all known-answer vectors:

```sh
go test ./...
```

With `-short`, the slow tests run only for `Fast1`.

On amd64, the field multiplication uses the BMI2 and ADX instructions if the
CPU supports them. The tests check that code against the Go code. To test the Go
code by itself, as on other architectures, use the `purego` build tag:

```sh
go test -tags purego ./...
```

Also test the AVX2 vector code, which is compiled only with
`GOEXPERIMENT=simd`, and the scalar fallback of that build:

```sh
GOEXPERIMENT=simd go test ./...
GOEXPERIMENT=simd GODEBUG=cpu.avx2=off go test ./...
```

The tests of the vector code check it against the scalar code. On a CPU
without AVX2, they are skipped.

The tests of `internal/asmgen` run in its own module:

```sh
go test -C internal/asmgen ./...
```

## Run the linter

The code passes [golangci-lint](https://golangci-lint.run) v2 with all linters
enabled:

```sh
golangci-lint run --default=all ./...
golangci-lint run --default=all --build-tags purego ./...
GOEXPERIMENT=simd golangci-lint run --default=all ./...
(cd internal/asmgen && golangci-lint run --default=all ./...)
```

## Keep secret computations constant time

Code that handles private keys must not branch on secret data or use it to
index memory. Express secret conditions as `uint64` values that are 1 or 0,
and apply them with helpers such as `selectFrom`, `swap`, and `condNeg`.

The field multiplication with the BMI2 and ADX instructions follows the same
rules: it has no branches, and it selects the reduced result with `CMOV`.
